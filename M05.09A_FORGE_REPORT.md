## Generated and manual work

Forge accepts strict `PackProposalV0`, compiles it into the production
`PackBundle`, and can preview/materialize a local skeleton containing manifest and
ActionCard declarations, runtime factory/registration seams, fail-closed executor
and verifier stubs, structural tests, README, and OSS provenance.

Developers still implement canonical state, database/migrations, integrations,
executor behavior, verifier truth, authorization/lifecycle operations, and domain
semantics. A defensible estimate is that Forge removes roughly half of the
repeated structural Pack setup for a small Pack; it removes none of the domain
truth or safety work.

## Core impact and security

One generic public `validate_pack_bundle` seam was extracted from `PackManager` and
is reused by Forge. This is a **GENERIC MISSING PRIMITIVE**, with zero domain
leakage. Forge writes no files during compilation, installs/enables nothing,
grants no permission, invokes no model or service, and generated runtimes raise
`NotImplementedError` rather than reporting execution or verification success.
The existing PackManager lifecycle remains the authority: Aquarium 0.1 read-only
to 0.1 read+write stays pending until explicit approval, and the active Pack
remains usable.

## Acceptance evidence

Tests prove deterministic compilation, shared validation, malformed namespaces,
undeclared permissions, permissioned actions without verification, exact generated
ActionCard/runtime parity, fail-closed stubs, and lifecycle permission expansion.
The Aquarium proof requires no Aquarium-specific Core code.
